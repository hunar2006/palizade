# M1: core matcher hardening (lane A)

## Features and commits

- `3d40e65`: stripped matching-only hidden Unicode, original-offset heuristic spans, escaped hidden-character metadata and compact token/host skeletons; benign emoji stays unchanged.
- `e5b85ca`: bounded recursive decoding for sink text/fields and both taint classes; payload-free `decoded:<kind>` audit reasons and policy `on_error` on decision failure.
- `286535e`: per-tool JSON-path role overrides and common GitHub/Slack/mail/fetch role mappings, including channel/account IDs.
- `76453cb`: untrusted destination provenance and lookalike host blocks before generic sink rules. Shared email domains do not taint unrelated recipients.
- `cb18fdf`: open/approve-new/allowlist-only egress, allow once/always/deny in both approval providers, atomically persisted learned grants with reload on use.
- `45c4de1`: bounded session/destination split correlation; sensitive eight-character shard fingerprints stored as HMACs in SQLite.

## Configuration defaults

- `servers.<name>.argumentRoles`: `{}`; per-tool mapping of JSON paths to roles.
- `taint.decode.maxDepth`: 2; `maxBytes`: 262144 total decoded bytes per expansion.
- `egress.mode`: `open`; `egress.learnedFile`: `palizade.allow.yaml` beside config.
- `egress.allowlist.destinations`: `[]` for typed channel/account/repository IDs.
- `taint.window.calls`: 12; `ttlMs`: 900000; `maxBytes`: 262144; `maxDestinations`: 256.

## Policy conditions and behavior changes

New conditions: `tainted_destination`, `lookalike_destination`, `new_destination`, `split_match`.

Default, strict, egress and interactive block observable untrusted destination provenance and known-host lookalikes. Strict blocks unallowlisted sink destinations even when config mode is open. Default recommends approve-new; the config default remains open. Default requires approval for split matches; strict and egress block them. Hard policy blocks cannot be bypassed by remembered egress grants. Audit-only has no new enforcement rules.

## Validation

`pnpm build`, `pnpm test --maxWorkers=2` (94 tests, 25 files), `pnpm smoke:filesystem` pass. The official filesystem server returned 14 tools and handled a 655434-byte payload. The initial fully parallel suite timed out in two existing SQLite tests; limiting local workers to two passed without changing test assertions/timeouts.

`pnpm bench:latency`: engine p50 0.10 ms / p95 0.23 ms; SQLite 4KB ingestion p50 4.93 / p95 6.42 ms; SQLite sink matching against 200 records p50 1.79 / p95 2.57 ms. The SQLite benchmark measures store matching, not a full HTTP/hook path.

## Shortcuts and verification limits

- `packages/taint/src/unicode.ts:5`: compact Latin-lookalike table; full UTS 39 data is deferred until broader identifier coverage is needed.
- `packages/taint/src/decode.ts:46`: common named HTML entities; numeric entities are supported, less common names require table extension.
- `packages/taint/src/window.ts:4`: rolling text is bounded, memory-only and process-local; cross-process split correlation would need an authenticated encrypted store. No raw outbound window is persisted.
- `packages/taint/src/fingerprint.ts:41`: sensitive shard coverage is limited to 2048 eight-character fragments. Previously stored fingerprints cannot be retroactively regenerated without source text.
- Existing `packages/taint/src/fingerprint.ts:51`: winnowing remains bounded; long-response coverage outside those fragments still relies on tokens/fuzzy/temporal signals.
