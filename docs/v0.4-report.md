## Conditions and capabilities

New policy conditions: `tainted_destination`, `lookalike_destination`, `new_destination`, `split_match`, `rule_of_two`, `destination_session_trusted`, `rate_limited`, `loop_detected`, `critical_path`, `argument_path_glob`, `output_path_allowed`, `git_push_unapproved`, `tool_shadowing_detected`, `name_collision_detected`, `hidden_unicode_detected`. `taint`/`sensitive_taint` require observable matches; temporal-only evidence stays in `temporal_taint`. Destinations include tool-specific IDs as well as hosts/email. Matching views strip hidden characters and fold only domain/identifier lookalikes; displayed text remains unchanged unless the selected action transforms it. Decode failures/budget exhaustion follow policy on_error.

## Behavior changes and integration decisions

- Default/interactive/strict/egress block copied destinations and known-host lookalikes before generic sink rules. Strict blocks new destinations even with open mode. Default recommends approve-new but the compatibility default stays open; remembered grants live separately and cannot override hard blocks. Legacy `@domain` email patterns remain supported.
- Default approves split matches; strict/egress block them. Rolling windows retain raw text only in bounded process memory; query values are included and percent-decoded before concatenation. No raw outbound window is stored on disk.
- Default/strict/interactive gate remote/message/memory actions once both exposure flags are set, even for paraphrases. Flags/counters/grants persist in SQLite. Without PALIZADE_RUN_ID, profile exposure conservatively spans wrapper restarts; client hook session IDs do not override profile scope. Session grants suppress only Rule of Two/approve-new.
- Enforcing presets gate quarantine/rates/loops after hard blocks; research gates otherwise permitted output. Quarantine starts on high-score source/tool content or blocked copied/lookalike/split destinations, expires on TTL/turn bounds at the next sink, and audits start/end/clear separately. Clearing it leaves exposure flags active.
- Critical writes are approval-gated after hard blocks. Strict/coding block tainted critical writes; research blocks every critical write. Paths resolve home/traversal/symlink ancestors and platform case, including hidden worktree ancestors. Entire package.json writes are protected. Default's existing general copied-content block can still deny a tainted critical write.
- Memory writes now carry persists_memory. Default/interactive/egress approve tainted memory as an explicit exception to their generic copied-content block; strict blocks it. Approval promotes original provenance and stores observable transformed fields persistently; later reads retain original identities within the profile.
- Semi/untrusted annotations can raise risk but no longer turn a risky/unknown tool read-only. Trusted annotations and explicit administrator classification retain precedence. Name/description heuristics remain conservative and may overclassify sources.
- Metadata collisions/shadowing block offending tools; hidden metadata Unicode is sanitized after hard blocks. Audit-only logs findings. Common built-in names are labelled, not blocked. Collisions depend on wrapped servers sharing a state directory and their list registration order. Lockfiles now store snapshots; approve prints escaped diffs and asks in a TTY, while scripts retain compatibility.
- All enforcing presets approve elicitation; sensitive form fields remain denied. Strict suspicious output now blocks before its former strong-signal sanitization rule. Copied query/destination and split/secret hard blocks precede approval/redaction. Egress allow/PII-redaction exceptions require no critical/temporal/quarantine/rate/loop gate; copied data retains its explicit allowlisted exception.
- Coding/research are opt-in. Coding adds tainted shell/critical blocks, sensitive/Rule-of-Two network/DNS/ICMP shell blocks and unverified Git push approval. Research permits sources and local output writes only; critical, remote, memory, execution/deletion and unknown tools remain blocked. Explicit source overrides are an administrator trust decision.
- Init embeds current presets and preserves files unless forced; strict init selects allowlist-only. Listener token contents are never printed by init. Optional captured tainted payloads are wholly masked; copied destinations are masked in audit/approvals. Known secret/PII masking remains for other captured content.
- Wrap/serve reload valid policy/config/allowlist changes by default. Bad edits keep the last valid state and are audited/warned; disabling reload preserves fail-closed learned-file errors. Startup remains fail-closed. Restart-only settings are reported. Unknown config keys now produce validation errors with paths/lines/hints.
- HTTP, hooks and optional sandbox launch preserve the shared engine. Spawn auditing and doctor output add visibility; metrics remain off by default. Runtime error/validation messages and status JSON gain fields, and lockfiles/audit storage grow. No package release or main push was performed by this build.

Shared rebase conflicts retained M4 metadata fields, M5 MRTR/relock/era fields and M3 provenance fields. New-era inputResponses continue to contribute observable taint while temporal-only sensitive evidence is excluded. Typed HTTP/MRTR fixtures were extended only with new defaults.

## Verification and remaining limits

- M1/M3 checked the live MCP tools/changelog annotation-trust requirement. Lane B reports live transport/MRTR/elicitation/hook-doc checks; lane C checked the changelog. Full discover/subscription result schemas were not verified by those milestones. FINAL checked live [authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) and [token-passthrough guidance](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices#token-passthrough): tokens need the intended resource audience; this listener is not a validated OAuth-terminating gateway. Avoiding TLS termination alone does not prove audience compliance. No OAuth server/token minting was built.
- Input-required gating is currently tool-result-only. Prompt/resource input-required results are not inspected by that handler. Discover shapes without a top-level tools array are scanned without tool hashing. Structured spotlighting preserves non-string fields but can exceed string schema constraints. These are lane B partial features, documented rather than silently advertised as full coverage.
- Listener inbound standard headers are checked, but Mcp-Param values are not fully schema-compared there. Known-schema outbound parameter checks remain. Modern JSON-only clients receive the final response rather than streamed notifications; a long-lived subscription relay is not implemented. Legacy listener clients share one upstream session per server; per-client bridges avoid that session sharing.
- Native adapters were unit-tested; live installed Claude Code/Cursor/Codex activation was not rerun in FINAL. Cursor ask behavior depends on the client, and shell parsing is heuristic. Hook engines are one-shot, so their split windows do not survive invocation boundaries. Profile/run scope controls exposure sharing.
- Docker was unavailable on this Windows host, so the actual container test is skipped; bubblewrap/seatbelt and Linux/macOS/Node 22 execution were not run here. Sandbox allowlist mode needs backend enforcement: a hostile server can ignore proxy variables on Docker's default bridge, and raw TCP is not filtered there or by bubblewrap's allowlist mode. Seatbelt permits broad reads. Remote servers/client/host are not sandboxed by Palizade.
- Protected paths are local observations, not enforcement of a malicious server's I/O or a later symlink race. Unfamiliar edit formats cannot display a full proposal diff. Explicit overrides and approvals are administrator trust decisions.
- Matching is bounded observable provenance, not general semantic equivalence. Token confusables/entity tables are compact; fingerprint/shard coverage is limited; independently padded encoded shards and cross-process splits can evade window concatenation. Stored old fingerprints cannot gain new shard views without source text. Persistent memory matching does not recognize arbitrary semantic rewriting.
- Hot reload with several served URL servers was not exercised end to end; polling was tested on Windows. An in-flight message may observe new options partway through processing. Status/learn load whole audit files; learn does not infer repository/channel/account allowlists. Policy check detects syntactic catch-alls and selected impossible conditions, not full semantic subsumption.
- Serious/adaptive model evaluation was not run. The current 0% ASR remains in-sample. [Evaluation plan](evaluation-plan.md) covers AgentDojo, MCPTox, MPBench, plausible held-out InjecAgent sinks, benign copy utility/approval cost and adaptive M1 bypasses. Client-rendered exfiltration, host compromise and malicious bypassing clients remain outside observable traffic.

## Current shortcut comments

The following inventory is generated from the integrated source. Historical lane reports may use earlier line numbers or mention comments that were only documented; this list records the comments actually present.

- `packages/taint/src/fingerprint.ts:41`: sensitive shard coverage is bounded to 2048 eight-character fragments, raise the bound for larger sensitive outputs.
- `packages/taint/src/fingerprint.ts:51`: stops after `max` fragments (~17 KB of text); injections past that rely on token, fuzzy and temporal matching. Raise max or switch to sampled coverage if long pages matter.
- `packages/taint/src/decode.ts:46`: common named HTML entities only, extend the table when uncommon named entities appear in attacks.
- `packages/cli/src/index.ts:553`: loads the whole JSONL audit file into memory like `palizade audit`; stream it line by line if audit files reach hundreds of MB.
- `packages/policy/src/check.ts:85`: only syntactic catch-alls are detected, not a later rule fully covered by earlier narrower rules; add condition subsumption if users hit that.
- `packages/cli/src/status.ts:82`: reads the whole JSONL audit file like `palizade audit`; switch to the SQLite sink's indexed query if audit files grow past tens of MB.
- `packages/core/src/classifier.ts:13`: verb match only, so read tools like get_transfer_history also become sinks (over-block, fails closed).
- `packages/taint/src/window.ts:4`: independently padded encoded shards may obscure concatenation, add per-shard decoded windows when adaptive evaluation requires them.
- `packages/taint/src/window.ts:5`: outbound windows are process-local memory only, use an authenticated encrypted shared store for cross-process split correlation.
- `packages/core/src/hooks.ts:26`: native hooks have no tools/list metadata lock, extend native capability mapping when supported clients add tool types.
- `packages/core/src/hooks.ts:76`: each one-shot hook opens a fresh engine/store, use a persistent daemon if hook startup latency or shared split windows are required.
- `packages/core/src/hooks.ts:132`: heuristic shell extraction misses complex quoting and indirect destinations, use a shell parser if supported command forms require it.
- `packages/core/src/git-egress.ts:12`: only simple literal git push remotes are resolved, require approval for dynamic/compound commands and extend parsing when needed.
- `packages/taint/src/unicode.ts:5`: compact common Latin lookalikes only, use the full UTS 39 table for broader identifier coverage.
- `packages/core/src/http-listener.ts:407`: inbound parameter headers are not schema-compared here, add per-client schema-aware checks when full inbound Mcp-Param support is required.
- `packages/core/src/interceptor.ts:105`: a message already being processed may evaluate later rules against the new document; snapshot options per message if mid-message consistency is ever required.
- `packages/core/src/interceptor.ts:701`: discover shapes without a top-level tools array are scanned but not tool-hashed, extend schema-aware locking when more discover shapes are supported.
- `packages/core/src/interceptor.ts:739`: input-required gating runs only for tools/call results, extend prompt/resource handlers when those result forms are supported.
- `packages/core/src/launch.ts:27`: on Linux, docker containers reach the host through the docker bridge, so the proxy listens on all interfaces behind a per-launch credential; bind to the bridge address once it is discoverable without shelling out to docker.
- `packages/core/src/protected-paths.ts:89`: unfamiliar edit formats cannot produce a full diff, add adapters when a supported tool supplies another edit format.
- `packages/core/src/sandbox.ts:200`: seatbelt allows reads everywhere (node and npm read across the system), restrict reads once a per-runtime read list is maintained.
- `packages/core/src/sandbox.ts:270`: allowlist relies on HTTP(S)_PROXY, which a hostile server can ignore on the default bridge network; set sandbox.dockerNetwork to an internal network whose only route is the proxy for hard enforcement.
- `packages/core/src/sandbox.ts:312`: relative commands rely on PATH entries under /usr, /bin, /opt or /nix being bound; version-manager installs in $HOME (nvm, volta) need an absolute command path.
- `packages/core/src/metadata-guard.ts:162`: collisions are checked when this server answers tools/list, so a second server that registers the same name later is only caught on its own list, re-check on tools/call once list_changed handling (M5) refreshes the registry.
- `packages/core/src/metadata-guard.ts:229`: object keys are scanned but not rewritten (renaming schema properties would break calls), sanitize keys once a schema-aware rewriter exists.
- `packages/core/src/text.ts:44`: spotlighting can exceed structured string maxLength constraints, use schema-aware wrapping when result schemas are available.
