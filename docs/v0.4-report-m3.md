# M3: protected targets and memory sinks (lane A)

## Features and commits

- `9f85bf1`: semi/untrusted tool annotations can raise risk but cannot lower it; explicit administrator classification remains authoritative.
- `45b769d`: critical-path and output-directory checks resolve traversal, home paths, symlink ancestors and platform case rules; bounded approval diffs escape nonprinting characters and mask tainted/sensitive text.
- `0e68240`: memory/vector writes carry `persists_memory`, approval promotes original taint to durable untrusted provenance, and subsequent matching reads retain source identities across TTL/run boundaries within the profile.
- `2bfdf0c`: opt-in coding/research presets, bounded local Git remote resolution and `init --preset` with current embedded presets and optional `--output-dir`.

## Configuration defaults

- `protectedTargets.criticalPaths`: `[]` (additional patterns; built-ins remain active).
- `protectedTargets.maxDiffBytes`: 65536 per before/after view.
- `protectedTargets.outputDirectory`: unset; research output writes are blocked until configured. `loadConfig` resolves the directory beside the config and protects the actual config path.
- No runtime dependencies added. Persistent memory fingerprints have no expiry; `taint prune --include-persistent` explicitly removes them. Ordinary pruning retains them.

## Conditions and behavior

New conditions: `critical_path`, `argument_path_glob`, `output_path_allowed`, `git_push_unapproved`; new capability `persists_memory`.

All enforcing presets approval-gate critical writes after hard blocks. Strict blocks tainted critical writes explicitly; default retains its existing generic copied-content block. Entire package.json writes are protected, not only scripts. The normal source-file write path remains usable. An unresolved/nonregular/oversized diff fails through `on_error`.

Default, interactive and egress approve tainted memory writes before their generic tainted-sink block; strict blocks them. Destination and secret hard blocks stay authoritative. Rule of Two now includes memory sinks. Temporal-only matches populate the temporal condition without claiming observable copied content; new-era input-response matches remain included.

Coding contains the combined default rules, then adds tainted shell/critical-target blocks, sensitive/Rule-of-Two shell network/DNS/ICMP blocks and unverified Git push approval. Research permits sources and local writes whose every target is inside the output directory, excluding critical targets and network/remote/memory/execution/deletion capabilities. Unknown tools are blocked. Explicit source classification is needed for read tools with names implying network writes. Both presets retain merged M4 metadata rules; coding also retains M5 elicitation rules.

`init` defaults to the default preset, copies the actual bundled policy and preserves existing files unless forced. Strict initialization sets `egress.mode: allowlist_only`. Existing configs gain optional defaults at parse/runtime boundaries. An annotation on a semi/untrusted server may no longer make a risky tool appear read-only.

## Validation

After rebasing onto M4/M5/M9, build passes and 168 tests pass in 38 files, with one actual Docker launch test skipped. Tests use `--maxWorkers=2 --testTimeout=30000` to avoid Windows shared-disk contention; assertions are unchanged. Filesystem smoke passes with 14 tools and a 655434-byte payload.

Benchmark p50/p95: engine 0.13/0.29 ms; SQLite 4KB ingestion 4.37/5.29 ms; SQLite sink matching versus 200 records 1.59/2.15 ms. Sink p95 is below 15 ms. This benchmark measures store matching, not end-to-end transport/approval latency.

## Shortcuts, limits and integration

- `packages/core/src/git-egress.ts:12`: only simple literal Git push remotes are resolved; dynamic/compound/unsupported forms require approval. Local Git execution has a one-second timeout and 4096-byte output cap, without network access.
- `packages/core/src/protected-paths.ts:89`: unfamiliar edit formats cannot produce a full diff; approvals explicitly state the missing replacement content. Extend adapters when supported tools introduce new edit formats.
- Existing classifier verb heuristics can overclassify read tools as sinks (`classifier.ts:13`); retained unchanged.

Path checks observe the local filesystem at decision time; they cannot control a malicious server's actual writes or a subsequent symlink race. Persistent matching recognizes observable text transformations covered by the matcher, not arbitrary semantic rewriting. No serious model evaluation was run, and fixtures/results/eval were untouched. MCP annotation trust was checked against the live official tools specification during M1; no additional unverified spec behavior was introduced here.

Rebase conflicts retained both metadata/MRTR audit fields and memory provenance, and combined new-era input-response taint with temporal-only filtering. M5's typed test config gained only protected-target defaults. PR-only GitHub rules reject direct v0.4 updates; the already documented self-merged PR route is used, without force or a push to main. The same local lane branch continues through all milestones.
