# M2: session gates (lane A)

## Features and commits

- `a6fd577`: persisted Rule of Two exposure flags, paraphrase-independent remote-sink approval and bounded HMAC destination grants for a logical session.
- `9f9a12b`: shared quarantine, high-score/destination/split triggers, TTL/turn expiry, separate start/end/clear audit events and `palizade session quarantine --clear [--session <id>]`.
- `3e9673c`: atomic shared sink-rate, destination-count and identical-call tracking; all enforcing presets approval-gate limits/loops. Sensitive-path regex errors validate at startup, response decision errors follow `on_error`.

## Configuration defaults

- `taint.quarantine.scoreGte`: 0.85; `turns`: 20 sink attempts; `ttlMs`: 1800000.
- `limits.sinkCallsPerMinute`: 60; `distinctDestinations`: 20; `repeatThreshold`: 5; `historyEntries`: 1000.
- Exposure flags and grants follow configured scope; `PALIZADE_RUN_ID` isolates logical sessions by profile plus run when supplied. Profile mode shares flags across wrapper processes and launches otherwise. Process mode isolates sessions.
- Session destination grants have a fixed 1024-entry bound; session tracking exhaustion gates rather than discarding evidence.

## Policy and behavior changes

New conditions: `rule_of_two`, `destination_session_trusted`, `rate_limited`, `loop_detected`. The existing `session_quarantined` condition is now populated.

Default, strict and interactive gate network/message/remote-write sinks once both exposure flags are set, even without copied argument text. Session grants bypass only Rule of Two and approve-new, never hard blocks/quarantine/rate/loop limits. M3 adds memory capability to this gate. All enforcing presets gate quarantined sinks and limits/loops. The egress allowlist exception now requires inactive quarantine/rate/loop flags. Denied attempts count toward limits. Clearing quarantine leaves exposure flags active.

## Validation

Build, 103 tests in 27 files, real filesystem smoke and latency benchmark pass before the final CLI-clear regression test. The official filesystem smoke returned 14 tools and handled 655434 bytes. Tests use two local workers as in M1.

Benchmark: engine p50 0.14 / p95 0.42 ms; SQLite 4KB ingestion p50 5.47 / p95 8.05 ms; SQLite sink matching against 200 records p50 1.66 / p95 2.32 ms (under 15 ms). Store benchmark numbers do not measure the whole session gate/approval/transport path. The completion-marker commit records final test count after rebase.

## Limits and integration

No new shortcut comments or runtime dependencies. Without a host run ID, profile exposure flags persist conservatively across launches; use a new `PALIZADE_RUN_ID` for a fresh logical run. Session limits and grants are bounded and persisted as timestamps/counters/HMACs, not payloads. Quarantine expiry events are emitted when the next sink examines expiry. Serious model/adaptive evaluation remains deferred by the plan.

GitHub enforces PR-only updates on `v0.4`; direct milestone push was rejected during M1. Milestones are rebased and verified, then merged into `v0.4` through a self-merged integration PR. No push to `main` and no branch protection bypass. No fixtures, eval harness or ASR changes.
