# M4: tool metadata hardening (lane C)

## Features and commits

- `cea85dd`: metadata review for `tools/list`, prompt/resource lists and `server/discover`. Every string and property name (descriptions, titles, schema `description`, `default`, `enum`, `examples`, `const`) is checked for hidden Unicode outside valid emoji sequences, TAG payloads are decoded back to ASCII and run through the detectors, dangerous defaults are labelled, and tool names are compared across wrapped servers through a shared SQLite registry (`<stateDir>/tool-registry.sqlite`) for collisions and shadowing. Flagged tools get their own policy decision: blocked tools are withheld from the list and later `tools/call` requests for them are blocked; sanitized tools have hidden characters stripped. Preset rules added.
- `f174c35`: faithful approval. Lock entries now store a canonical snapshot beside the hash. New `palizade lock diff <server> [--json]` prints a field by field diff with byte offsets and every non printing character escaped as `\u{XXXX}`; exit code 2 when anything differs. `palizade lock approve` prints the same diff first and asks for confirmation in an interactive terminal (`--yes` skips it).
- `41537f1`: docs (`docs/policy.md`, `docs/architecture.md`, `README.md`).

## Configuration defaults

All optional, in a new `metadata` block:

- `metadata.shadowing`: `true`. Turns the cross-server shadowing check on or off.
- `metadata.builtinNames`: `["read_file", "write_file", "bash", "fetch"]`. These names get the label `builtin_tool_name` (not blocked).
- `metadata.dangerousDefaults`: `[]`. Extra substrings treated as dangerous in `default`, `enum`, `examples` and `const` values, on top of the built in list (`--no-sandbox`, `--dangerously-skip-permissions`, `--dangerously-bypass-approvals-and-sandbox`, `--yolo`, `--disable-web-security`, `--allow-all`, `autoApprove`, `auto_approve`, `bypassPermissions`, and boolean properties such as `autoApprove` or `yolo` with `default: true`).
- `metadata.maxScanBytes`: `262144`. Cap on the metadata text scanned per tool or descriptor.

The registry path is fixed at `<stateDir>/tool-registry.sqlite`; it holds tool names only.

## Policy conditions

- `tool_shadowing_detected`
- `name_collision_detected`
- `hidden_unicode_detected`

New detector labels: `hidden_unicode`, `tool_shadowing`, `tool_name_collision`, `builtin_tool_name`, `dangerous_default`, and `hidden:<label>` for detector hits inside a decoded TAG payload.

## Behavior changes to presets and existing users

- `default`, `strict`, `egress`, `interactive` and the `palizade init` template have a `# --- M4 ---` block after `deny-server-sampling`: `block-tool-name-collision`, `block-tool-shadowing`, `sanitize-hidden-unicode-metadata`. `audit-only` logs the same three findings.
- If two wrapped servers that share a state directory expose the same tool name, the second one to answer `tools/list` loses that tool. After the first server restarts, both copies are withheld until one server is renamed or removed from `palizade.yaml`.
- On `tools/list` the metadata conditions are evaluated per flagged tool. A block withholds that tool only; the rest of the server keeps working. Tools that are not flagged get no extra policy evaluation, so existing policies behave as before for clean metadata.
- Built in name matches (`read_file`, `write_file`, `bash`, `fetch`) are labelled but **not** blocked. The plan lists them as hijack candidates, but the reference filesystem and fetch servers use exactly those names, so blocking them would break the most common installs (the filesystem smoke test included).
- A dangerous default raises that tool's detector score to 0.4, so the default presets spotlight its description (the existing `fused.score >= 0.35` path).
- **Interaction with M1:** M1's heuristic adds 0.2 per hidden character. On metadata this pushed any TAG payload of four or more characters over 0.75, so `block-poisoned-tool-metadata` blocked the server's whole list before the per-tool rules could run. Metadata content detectors now see the hidden-stripped view, and the M4 review handles hidden characters, including detector scoring of the decoded TAG payload. A hidden instruction that scores 0.75 or more still blocks the whole list, the same as a visible one. M1 behavior for tool results and arguments is unchanged.
- `palizade lock approve` and `lock diff` also work for `url` servers from M7.
- Under `strict`, whose default action is `require_approval`, a tool flagged only for a dangerous default prompts for approval, because no specific rule matches it. `server/discover` mirrors `initialize`: it is audited and can be blocked, but never prompts.
- `palizade lock approve` now prints a diff and asks `Approve these changes? [y/N]` when stdin is a TTY and something changed. Non TTY runs (scripts, CI) behave as before. Old lock entries keep working; entries approved before v0.4 have no snapshot, so `lock diff` shows all current fields with a note.
- Lockfiles grow because each tool entry now stores its canonical snapshot.

## Validation

`pnpm build`, `pnpm test --maxWorkers=2` (137 tests, 32 files, after rebasing on M1, M2 and M7), and `pnpm smoke:filesystem` (14 tools, 655434-byte payload) all pass.

`pnpm bench:latency` after the rebase: engine p50 0.11 ms / p95 0.22 ms; SQLite 4 KB ingest p50 5.17 / p95 7.39 ms; SQLite sink check against 200 records p50 1.38 / p95 2.00 ms (limit 15 ms). Before the rebase (M4 alone): p95 0.17 / 8.28 / 2.00 ms.

`packages/taint/src/alignment.test.ts` occasionally hits the default 5 s timeout when the suite runs fully in parallel while `tsc` is also running. It passes on rerun. It is a pre-existing test that M4 does not touch.

## Shortcuts

- `packages/core/src/metadata-guard.ts:162`: collisions are checked when a server answers `tools/list`. A server that registers the same name later is only caught on its own list, not retroactively.
- `packages/core/src/metadata-guard.ts:229`: object keys are scanned but not rewritten when sanitizing; renaming schema properties would break calls.
- `packages/core/src/interceptor.ts:564`: `server/discover` output is scanned, not locked; M5 owns lockfile coverage for it.

## Not verified against the spec

- The 2026-07-28 changelog was read live: `server/discover` advertises versions, capabilities and identity, not tool lists, so M4 scans its strings like `initialize` metadata. I did not read the full `server/discover` result schema.

## Skipped or partial

- Built in name hijack is labelled but not blocked by default (see above). Users can block it with `labels_any: [builtin_tool_name]`.
- Shadowing only counts compound tool names (containing `_`, `-`, `.`, a digit or camelCase, at least 4 characters) or server-qualified mentions such as `github.create_issue`. Plain words such as `search` are ignored to avoid false matches on ordinary prose.
