# M9: optional sandboxed launch (lane C)

## Features and commits

- `9b4b295`: per-server `sandbox:` for stdio servers. `packages/core/src/sandbox.ts` validates the sandbox for the host platform and builds the launch plan for `docker`, `bubblewrap` or `seatbelt`; `packages/core/src/launch.ts` is now the single spawn point for `wrap`, `lock approve` and `lock diff`. `network: allowlist` starts a per-launch HTTP/CONNECT egress proxy (`packages/core/src/egress-proxy.ts`) that allows only `allowHosts` and audits every decision as `sandbox/egress`. Every spawn is written to audit (`process/spawn`) before the process starts, with secrets masked; a failed audit write refuses the spawn.
- `8de09f3`: CLI wiring. `wrap` and the lock commands pass the audit logger into the launch, and `palizade doctor` prints a `Sandbox:` section that marks each server `sandboxed`, `UNSANDBOXED`, `UNSUPPORTED` or remote, and exits 1 when a configured sandbox cannot run on this platform.
- `7359dbb`: docs (`docs/architecture.md` "Sandboxed Launch", README config example and limits bullet).

## Configuration defaults

All optional, nested under `servers.<name>.sandbox`. The string shorthand `sandbox: docker` equals `{ type: docker }`.

- `type`: `none`. One of `none`, `docker`, `bubblewrap` (Linux), `seatbelt` (macOS). On Windows only `docker` is accepted; anything else is a startup error naming the server.
- `image`: `node:22-slim` (docker only).
- `writable`: `[]`. Paths relative to the server `cwd` (or absolute) that are bound read-write. Docker accepts `host::/container`. Everything else under `cwd` is read-only.
- `network`: `none`. `allowlist` requires a non-empty `allowHosts` (exact host or `*.suffix`).
- `passEnv`: `[]`. Host environment variable names passed through; no other host environment reaches the server except the server's own `env`.
- `dockerNetwork`: unset. Name of a docker network to use in allowlist mode instead of the default bridge.
- `pidsLimit`: `512`. `memory`: unset (docker `--memory`).
- Fixed bounds: the egress proxy accepts at most 64 concurrent connections, closes idle tunnels after 120 s, and requires a random per-launch proxy credential.

A `url` server with a `sandbox` is a config error.

## Policy conditions

None. M9 adds no policy conditions; spawn and egress events are `log_only` audit events.

## Behavior changes to presets and existing users

- No preset changes. Servers without `sandbox` launch exactly as before (same command resolution, same environment).
- Every stdio launch now writes one `process/spawn` audit event. Audit grows by one line per launch. `lock approve` and `lock diff` write it to the configured JSONL audit file.
- `palizade doctor` now lists unsandboxed servers. It only fails (exit 1) for a sandbox that is unsupported on this platform, not for unsandboxed servers.

## Shortcuts

- `packages/core/src/sandbox.ts:200`: seatbelt allows reads everywhere; writes and network are restricted.
- `packages/core/src/sandbox.ts:270`: docker allowlist mode on the default bridge relies on the server honoring `HTTP(S)_PROXY`; set `dockerNetwork` to an internal network for hard enforcement.
- `packages/core/src/sandbox.ts:312`: bubblewrap with a relative command depends on PATH entries under `/usr`, `/bin`, `/opt` or `/nix`; version-manager installs in `$HOME` need an absolute command.
- `packages/core/src/launch.ts:27`: on Linux the proxy for docker listens on all interfaces (protected by the per-launch credential) because containers reach the host through the docker bridge.

## Skipped or partial

- No proxy for raw TCP egress: allowlist mode covers HTTP and HTTPS (CONNECT). Other protocols are blocked under `network: none`; in allowlist mode they are only blocked when the sandbox network itself has no other route (docker `dockerNetwork` set to an internal network, or seatbelt, which only permits the proxy port). With bubblewrap or the default docker bridge, raw TCP is not filtered.
